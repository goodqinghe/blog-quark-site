通过 GitHub Actions 构建博客 ​

大致思路 ​

背景 ​

之前博客的发布流程是手动的：在本地写好文章 → 运行 quarkdown c blog.qd 构建 → rsync 同步到发布仓库 → 手动 git push。每次发布都要重复这几步，而且换一台电脑还得先装好 Quarkdown 环境，很麻烦。

于是就想：能不能像那些正经项目一样，往 GitHub 上一推，剩下的全部自动搞定？

答案是可以的，而且不需要额外服务器，GitHub Actions 免费额度完全够用。

整体方案 ​

整个流程拆成三块：

mermaid
flowchart LR
    A["写完文章 git push"] --> B["GitHub Actions 自动触发"]
    B --> C["安装 Quarkdown → 构建 HTML"]
    C --> D["推送到公开仓库"]
    D --> E["Cloudflare Pages 自动部署"]

两个 GitHub 仓库分工明确：

  1. blog-quark-src（私有）：存放 .qd 源文件、图片、PPT 等，只有自己看
  2. blog-quark-site（公开）：存放构建好的纯 HTML 文件，用于 Cloudflare Pages 部署

前置准备 ​

首先要建好两个仓库，然后在 GitHub 上配置一个 Personal Access Token (PAT)，让 Actions 有权限把构建产物推到公开仓库。

创建 PAT 的步骤：

  1. GitHub → Settings → Developer settings → Personal access tokens → Tokens (classic)
  2. 点 Generate new token (classic)
  3. Note 随便填，比如 blog-deploy
  4. 勾选 workflow 和 repo 权限
  5. 生成后复制 token

然后在源码仓库 blog-quark-src 中：

  1. Settings → Secrets and variables → Actions
  2. New repository secret
  3. Name 填 GH_PAT，Value 粘贴刚才复制的 token

Cloudflare Pages 那边，在 Dashboard 里创建一个 Pages 项目，连接到 blog-quark-site 公开仓库。之后每次公开仓库有更新，Cloudflare 会自动重新部署。

编写 Workflow ​

在源码仓库的 .github/workflows/ 目录下创建 deploy.yml：

yaml
name: Auto Build and Sync Blog

on:
  push:
    branches:
      - main

jobs:
  build-and-deploy:
    runs-on: ubuntu-latest

    steps:
      # 1. 检出源码仓库
      - name: Checkout Source Code
        uses: actions/checkout@v4

      # 2. 安装 Quarkdown
      - name: Setup Quarkdown
        uses: quarkdown-labs/setup-quarkdown@v1

      # 3. 构建博客，生成静态 HTML
      - name: Build Blog HTML
        run: quarkdown c blog.qd

      # 4. 复制额外文件（如 PPT）
      - name: Copy Extra Files
        run: |
          cp -r my-ppts quarkdown-output/qinghelog/

      # 5. 推送到公开发布仓库
      - name: Push to Public Static Repo
        uses: cpina/github-action-push-to-another-repository@main
        env:
          API_TOKEN_GITHUB: $\{\{ secrets.GH_PAT \}\}
        with:
          source-directory: "quarkdown-output/qinghelog"
          destination-github-username: "<你的 GitHub 用户名>"
          destination-repository-name: "blog-quark-site"
          target-branch: "main"
          commit-message: $\{\{ github.event.head_commit.message \}\}
          user-email: "<你的邮箱>"

各步骤说明 ​

步骤做了什么
Checkout Source Code把源码仓库的代码拉到 Actions 运行环境中
Setup Quarkdown使用 Quarkdown 官方 Action 自动安装构建环境
Build Blog HTML执行 quarkdown c blog.qd，产物默认输出到 quarkdown-output/qinghelog/
Copy Extra Files把 my-ppts/ 等额外目录复制到构建产物中一起发布
Push to Public Repo用 cpina/github-action-push-to-another-repository 把构建产物推到 blog-quark-site

关于密钥 ​

$\{\{ secrets.GH_PAT \}\} 就是前面在 GitHub 上配置的 Personal Access Token。GitHub 会对 secret 值自动脱敏，不用担心泄露。

关于 Push Action ​

cpina/github-action-push-to-another-repository 是一个社区 Action，核心功能就是：把当前仓库的某个目录，原样推到另一个仓库的指定分支。这里我们用它把 quarkdown-output/qinghelog/（构建产物）推到 blog-quark-site 的 main 分支。

验证效果 ​

把 deploy.yml 推到源码仓库的 main 分支后：

  1. 打开 GitHub 源码仓库的 Actions 标签页，能看到一个 Workflow 正在运行
  2. 运行成功后，打开公开仓库 blog-quark-site，能看到新的 commit
  3. Cloudflare Pages 检测到公开仓库更新，自动开始部署
  4. 等几十秒，刷新博客网址就能看到最新内容

从此以后，写博客的流程就变成了：

text
本地写文章 → git add → git commit → git push

剩下的构建、同步、部署全部自动化完成。

几个细节 ​

触发条件 ​

yaml
on:
  push:
    branches:
      - main

只有推送到 main 分支才会触发。如果你想在其他分支先测试，可以改成推到任意分支都触发，或者手动触发：

yaml
on:
  push:
  workflow_dispatch:   # 允许手动触发

commit message 同步 ​

yaml
commit-message: $\{\{ github.event.head_commit.message \}\}

这样公开仓库的 commit message 会和源码仓库保持一致，方便追溯"哪次提交对应发布的什么内容"。

如果不需要额外文件 ​

如果你的博客不需要复制 PPT 之类的额外文件，直接删掉 "Copy Extra Files" 那一步就行。

总结 ​

这套方案的核心思路其实就一句话：GitHub Actions 充当了"免费的 CI 服务器"，帮你做构建和推送这两件体力活。

相比之前手动构建的方式，好处很明显：

  • 不用在本地装 Quarkdown 环境，换了电脑也能发布
  • 不会忘了某一步（比如忘了 rsync、忘了 push）
  • 每次提交都有可追溯的构建记录
  • 完全免费，GitHub Actions 每月 2000 分钟额度个人用绰绰有余

后续还可以优化的方向：

  • 加上构建失败的通知（比如 Slack / 邮件）
  • 用 actions/cache 缓存 Quarkdown 依赖，加速构建
  • 加上 PR 预览：拉 PR 时也构建一份，方便预览效果
